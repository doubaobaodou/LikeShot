# LikeShot

一个 Windows 截图工具，界面和操作逻辑照着 QQ 的截图工具做，
但**和 QQ 共用同一个热键（Ctrl+Alt+A），并且只要 QQ 在跑就自动把热键让回去**。

也就是说：

- QQ 没开 → 按 Ctrl+Alt+A 弹的是 LikeShot 的截图层；
- QQ 一开 → 同一个键仍然唤起 QQ 自己的截图，LikeShot 全程不插手；
- LikeShot 从来不长占热键注册，所以 QQ 登录时不会弹「热键被占用」。

## 功能

| 能力 | 说明 |
| --- | --- |
| 截图 | 冻结屏幕 → 拖拽选区，自动吸附窗口（按 DWM 扩展边框，不含阴影），放大镜显示尺寸与取色 |
| 标注 | 矩形 / 椭圆 / 箭头 / 画刷 / 马赛克（像素格 + 高斯模糊两档）/ 文字 / 序号笔，16 色色板 + 三档线宽 |
| 完成 | 复制到剪贴板、存成 PNG/JPG/BMP、钉在桌面 |
| 长截图 | 纵向 / 横向滚动拼接，支持自动滚动，滚到底自动收尾 |
| 钉图 | 钉在桌面浮在最上层，滚轮缩放、四角等比拉伸、四边单向拉伸，可再进来继续标注 |
| 自由截图 | 选区状态下右键，多边形抠图，导出带 alpha |

快捷键：

| 键 | 作用 |
| --- | --- |
| `Ctrl+Alt+A` | 开始截图（QQ 在跑时让给 QQ） |
| `Enter` | 完成并复制到剪贴板 |
| `Ctrl+S` | 保存成文件 |
| `Ctrl+Z` | 撤销上一步标注（和 QQ 一样，没有重做） |
| `C` | 放大镜里按 = 复制当前像素色号 |
| `Esc` | 退出截图 / 关闭钉图 |
| 钉图上 `Ctrl+C` / `Ctrl+S` | 复制 / 保存钉图 |

## 热键避让是怎么做到的

`RegisterHotKey` 是独占的：谁先注册谁拿到，第二个人只会拿到
`ERROR_HOTKEY_ALREADY_REGISTERED (1409)`。QQ 在登录时就把 `Ctrl+Alt+A` 注册掉了，
所以只要 LikeShot 也去长占这个键，两边必然有一边「按了没反应」。

LikeShot 全程不注册热键，改用 `WH_KEYBOARD_LL` 低级键盘钩子分流，规则只有三条：

1. **让位名单里有进程活着**（默认 `QQ`、`Tim`，可在配置里改）→ 这个键一定是它的，
   直接放行，连一次注册试探都不做——试探有极小概率正好卡在 QQ 注册之前把它挤掉。
2. **让位名单都不在跑** → 试探一次 `RegisterHotKey` + 立刻 `UnregisterHotKey`：
   注册成功说明没人占，这个键由我们接管；失败说明被别的程序占了，继续放行，
   不做任何抢占。
3. 命中接管时把这次按键吃掉（keydown + keyup 都吞），避免系统里再冒出第二个响应者。

钩子回调必须 O(1)：低级钩子有 300ms 超时，超了 Windows 会**默默把钩子摘掉**，
之后热键就再也不经过我们了。所以回调里既不截图也不写日志文件，
截图用 `Dispatcher.BeginInvoke` 投递，日志也一样投递到 UI 线程再落盘。

配置在 `%APPDATA%\LikeShot\config.json`，日志在 `%LOCALAPPDATA%\LikeShot\log.txt`
（每次判定都会写一行：`让位 / 放行 / 接管`，出问题时先看这个文件）。

## 长截图拼接

滚动截图最容易翻车的地方是「重复贴一遍」。原因很实在：
页面里成百上千行是纯白的，它们的指纹完全一样，
拿这种行当锚点去算滚动量必然算错，于是每帧都把重叠区当新内容接上去。

拼接器的坐标关系是 `画布行号 = 帧行号 + 偏移量`，每帧解决两件事：

1. **偏移量**：只让「在画布里出现过、且只出现过一次」的行投票，取众数。
   白行/纯色行在画布里出现几百次，天然被这个条件排除。
   投票得到的是**绝对落点**而不是本次滚动量，这点搞混过一次，就是内容翻倍的那个 bug。
2. **哪些行是新增的**：从 `画布高度 - 偏移量` 接到帧尾，并且裁掉固定底栏
   （只有真的滚了一步才认这个尾带是底栏，静止页面里「尾部不变」只是内容没动，
   当成底栏裁掉会凭空吃掉几百行真实画面）。

判据不是「看起来差不多」：自检会造一张每条色带颜色都唯一的可滚动页面，
拼完逐行认色，要求识别出的序号严格递增、不重不漏。

## 构建

需要 .NET 8 SDK（WPF + WinForms 混用，仅 Windows）。

```powershell
cd src\LikeShot
dotnet build
dotnet run
```

跑起来后它在托盘里常驻。想立刻截一张：

```powershell
dotnet run -- --capture
```

## 自检

没有键盘也能验证核心链路，这几个模式都是无交互跑完自己退出的：

```powershell
# 选区 → 六种标注 → 导出 → 撤销，外加拼接器的三个合成场景
.\LikeShot.exe --selftest

# 长截图实跑：自己开一张 250 条唯一色带的滚动页面，自动滚到底，把长图写盘
.\LikeShot.exe --selftest --longtest

# 热键仲裁实跑：注入一次组合键，验「QQ 在名单里必须放行」和「没人占时必须接管」
.\LikeShot.exe --selftest --hotkeytest

# 只抓一张当前屏幕写盘，不弹任何界面（取证用）
.\LikeShot.exe --snap D:\path\screen.png
```

产物都落在 `%TEMP%\likeshot-selftest\`：`report.txt`、`long.png`、
`long-report.txt`（含逐帧判定）、`hotkey-report.txt`。

## 目录

```
src/LikeShot/
├── App.xaml(.cs)          进程入口、单实例、命令行模式
├── AppConfig.cs           热键、让位名单、保存目录/格式
├── Capture/               截图会话、屏幕抓取、长截图、导出、自检
├── Drawing/               标注图元、马赛克/模糊、离屏渲染
├── Geometry/              矩形扩展
├── Hotkeys/               组合键解析、低级键盘钩子、避让仲裁
├── Native/                Win32 互操作
├── Shell/                 托盘
└── UI/                    截图覆盖层、工具栏、图标、主题、钉图窗口
```

界面全部用代码画（没有 XAML 页面），图标是手算的矢量路径，
没有使用任何腾讯的图标、图片或代码。

## 已知边界

- 只测过单屏 + 3200×2000 @175% 这一档 DPI；多屏和混合 DPI 是按虚拟桌面物理坐标
  统一建模的，逻辑覆盖到了但没实跑过。
- 长截图遇到「一次滚超过一屏」会按整帧新内容接上，重叠部分会缺一段（宁可缺也不重复）。
- 页面里有懒加载/固定背景视差时，拼接结果取决于它实际渲染出来的样子。
- OCR（屏幕识图）、屏幕翻译、录屏没做，工具栏里也就没有这几个按钮。
